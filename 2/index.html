In this project, we were tasked with taking 3 red, green, and blue channel images of the same scene and aligning them to create a single color image. We implemented two methods to do this: a naive approach that exhaustively searches for the best alignment by optimizinng either the Euclidean distance or the normalized cross-correlation, and a more efficient pyramid approach that uses image pyramids to perform the alignment at multiple scales. The results were saved as images and can be viewed in the respective project folders.



Naive Implementation

My naive impelemtation involved creating a function that would take in the three color channels and align them using either the Euclidean distance or the normalized cross-correlation. I chose to use the normalized cross-correlation as my metric for alignment, as it is more robust to changes in lighting and contrast. The function would then return the aligned image, which was saved as a .jpg file. The results of my naive implementation can be seen below:



The alignment worked by shifting the green and red channels atop the blue channel by comparing 30x30 pixel patches of each image using either ncc or the l2 norm and lining up the patches that have the best scores. It's important to note that I also trim off 10% from each border of the image so we are only looking at center pixels. The images tested with the naive approach had a low resolution so this brute force approach worked fine. For the tif images though, a more efficient approach was necessary.



Image Pyramid Implementation

My pyramid implementation involved creating a function that would take in the same 3 color channels. Instead of brute forcing by searching the entire full resolution image, this function recursively shrinks the images resolution by half and aligns as it goes down, slowely refining the alignment to reduce the time complexity. Some extra examples

An issue that I ran into with the pyramid approach was that sometimes the alignment would be off by a few pixels, resulting in a blurry image. I believe this was due to the fact that the images were not perfectly aligned at the lowest resolution, and the error was compounded as the images were scaled back up. To fix this, I implemented a fine-tuning step at the end of the pyramid approach that would search a small window around the current alignment to find the best alignment. This plus some parameter tuning got me to a point of alignment that I was happy with.
